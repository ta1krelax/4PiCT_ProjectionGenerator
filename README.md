# CT 4π 锥束投影生成器 (CT 4π Projector)

两个独立的程序，一套代码库：

- **[projector_gui.py](projector_gui.py)（投影生成器）**：从 SolidWorks 导出的 STL
  模型出发，生成 4π 空间任意方向采样的锥束 X-ray 投影 (cone-beam projection)，
  耦合 ASTRA 重建 + SSIM 评估，自动搜索"要多少投影角度数 N 才能让重建质量落到
  目标 SSIM 附近"，支持批量跑一组不同的样品。需要 NVIDIA Warp 做 GPU 光追。
- **[recon_viewer_gui.py](recon_viewer_gui.py)（重建查看器）**：独立程序，导入
  已导出的投影数据集（或已经重建好的体积 `.npy`），跑 ASTRA 重建，用交互式
  3D 等值面（拖拽旋转/滚轮缩放/阈值可调）+ 可拖动的正交切片查看重建细节，还能
  跟一个参考 STL 算 SSIM、看重建耗时/算力信息，也能把等值面导出成 STL。从投影
  生成器里独立剥离出来，专门给"只是想看看重建结果/量化对比，不需要重新切片
  生成投影"这个场景用。

两者共用 [reconstruction.py](reconstruction.py)（ASTRA重建/SSIM）、
[mesh_viewer.py](mesh_viewer.py)（3D旋转缩放查看器）、[theme.py](theme.py)（扁平风
UI主题），但各自独立打包、独立运行，互不依赖。

（v1版本的重建查看器故意不带SSIM功能，为了不需要NVIDIA Warp、体积小很多；
后来发现"量化对比重建质量"是刚需，加回了SSIM对比功能——这就需要GPU ground
truth占据判定，绕不开Warp，所以现在两个exe体积基本一样大了，见下面"打包"
一节的说明。）

核心方法论：
- 投影生成阶段直接对 STL 三角网格做**解析光线-三角面片求交**（GPU 加速，
  NVIDIA Warp 的 BVH 光追），按 Beer-Lambert 定律累加射线穿过实体的路径长度
  得到吸收值 —— 不对模型体素化，因此和 ASTRA 重建用的体素网格是两套独立体系，
  避免 inverse crime 导致重建效果被"美化"。
- Ground truth（用于算SSIM的"标准答案"）单独用 GPU 光追做内外判定（射线穿过
  实体的次数奇偶性），在重建体素网格上逐体素判定，和重建结果严格对齐同一套
  网格，保证 SSIM 比较不会因为网格没对齐而失真。
- N 的搜索是"倍增找区间 + 二分收敛"：不知道目标N在哪就先倍增/减半找一个
  SSIM跨过目标值的区间，再在区间里二分，直到落在容差内或搜索次数用完；如果
  目标SSIM在给定的N范围内根本达不到（比如被体积分辨率或重建迭代次数卡住,
  不是N不够), 会如实报告"未达标 + 已尝试过的最好结果"，不会为了凑数字乱来。

基于 Python + NVIDIA Warp (GPU 光追) + ASTRA-Toolbox (GPU 重建) + scikit-image (SSIM)
+ trimesh (STL 处理) + PySide6 (GUI) + matplotlib (预览)。

## 安装

本机已经建好独立的虚拟环境 `.venv`（Python 3.14，含 GPU 版 warp-lang），
直接用它运行即可，不需要重新装：

```powershell
cd ct_4pi_projector
.venv\Scripts\python.exe projector_gui.py
```

重建查看器是同一套依赖（都装了），直接：

```powershell
.venv\Scripts\python.exe recon_viewer_gui.py
```

在别的机器上用，先建虚拟环境装依赖（需要 NVIDIA 显卡 + 驱动才能用 GPU 加速；
投影生成器没有 GPU 时 Warp 会自动退回 CPU 计算，结果一致只是慢一些；重建查看器
不用 Warp，但 ASTRA 的 GPU 重建算法本身还是需要 NVIDIA 显卡）：

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe projector_gui.py       # 投影生成器
.venv\Scripts\python.exe recon_viewer_gui.py    # 重建查看器
```

### 打包成独立 exe

不想装 Python 环境的话，可以打包成一个独立的 Windows exe（文件夹版，双击
`CT4PiProjector.exe` 就能跑，不需要另装 Python/依赖；仍然需要 NVIDIA 显卡+
驱动才能用 GPU，没有的话自动退回 CPU）：

```powershell
.venv\Scripts\python.exe build_exe.py
```

产物在 `dist\CT4PiProjector\`（整个文件夹一起分发，别只拷 exe）。打包脚本
打完会自动跑一次 `--selftest`（真的加载一个STL、跑一次GPU光追预览+一次ASTRA
重建，不是只看窗口能不能开），失败会报非零退出码。加 `--onefile` 可以打单文件
版，但体积大（warp-lang 自带完整JIT编译工具链），启动会明显更慢。

重建查看器是单独的打包目标（不会跟投影生成器打在一起）：

```powershell
.venv\Scripts\python.exe build_recon_viewer_exe.py
```

产物在 `dist\CT4PiReconViewer\`，同样会自动跑 `--selftest`（做一次等值面提取+
一次ASTRA重建+一次跟合成参考网格的SSIM对比）。加了SSIM功能之后这个exe也需要
Warp了，实测两个 exe 现在体积基本一样大（都是986MB）——如果你不需要SSIM对比
（只是导入/重建/看等值面），Warp不会被真正用到，但exe本身还是带着它，省不掉
这部分体积。

## 界面结构

主窗口只放三块内容：**中间 3D 模型预览**（左键拖拽旋转模型本身、坐标轴不动、
滚轮缩放）、**右侧投影预览画廊**（每次点"预览单张投影"新增一张缩略图，双击
弹出大图看细节/悬浮读像素值）、**下方日志**。

所有参数都收在顶部一行 tab 按钮里（输入/输出、旋转中心、锥束几何、材料、
采样与设备、样品评估、序列生成、批量实验(N搜索)），点一下弹出一个独立小窗口
调那部分参数，再点一下或关掉那个小窗口就收起；几个参数窗口互不影响，可以
同时开几个对照着调。

（原来这里还有个"单次重建实验"tab，现在已经拆到独立的重建查看器
[recon_viewer_gui.py](recon_viewer_gui.py) 里了，见下面单独一节。）

## 使用说明

1. **输入 / 输出**：点顶部"输入 / 输出" tab 弹出窗口，选择 STL 文件，点
   "加载并预览模型"（中间 3D 视图会显示网格，窗口里显示顶点数/面片数/
   水密性/包围盒/质心）；再选择输出目录。
   - 如果提示"非水密"，说明 STL 导出时可能不是严格的封闭实体（SolidWorks 导出
     STL 常见问题），路径长度积分可能有误差，建议回 CAD 里检查实体导出设置。
   - 每次加载新模型后会**自动跑一次像素尺寸自适配**（等价于手动点"锥束几何"
     面板里那个自动适配按钮），不用换个样品就手动点一次；如果当前SOD比模型
     半径还小算不出来，会在日志里说明原因，不会弹窗打断操作。
2. **旋转中心**：默认用模型质心（几何中心，自动算好），也可以切到"包围盒中心"
   或"手动输入" X/Y/Z 自己填。这个点就是 4π 采样时锥束绕转的中心，也是保存的
   ASTRA 几何向量的坐标原点。
3. **锥束几何（放大倍率）**：填 SOD（源到旋转中心的距离）和放大倍率 M
   （= SDD/SOD，SDD 会自动算出并显示），对应"beam source 和 detector 的相对
   位置"。
4. **像素密度**：探测器像素物理尺寸（mm/px）+ 分辨率（行 x 列），决定输出图像
   的像素密度和物理覆盖范围。
5. **材料**：给一个线性吸收系数 mu（1/mm），STL 本身没有材料信息，这里假设
   单一均匀材料的实体。
6. **4π 采样方案**：
   - `fibonacci_4pi`：全 4π 球面近均匀采样（推荐，用于采样密度实验）
   - `random_4pi`：全 4π 球面随机采样
   - `circular_x/y/z`：单轴 360° 圆周扫描（传统 CT 基线，用于对比/快速验证几何是否正确）
   - 填投影角度数 N。
7. **计算设备**：有 GPU 就选 cuda:0（自动检测），没有就用 cpu，两者输出结果一致。
8. **预览单张投影**：用当前参数只算第一个采样方向的投影，右侧显示灰度图，
   用来在跑全部之前先确认几何/曝光参数（放大倍率、mu、分辨率）是否合理。
9. **生成全部 4π 投影**：后台线程批量计算全部 N 个投影（不卡界面，有进度条），
   完成后保存到输出目录：
   - `projections.npy`：形状 `(N, rows, cols)`，float32，值是 `mu * 路径长度`
     （即 line integral，可直接喂给 FBP/SIRT/CGLS，不用再取对数）
   - `astra_vectors.npy`：形状 `(N, 12)`，ASTRA `cone_vec` 几何格式，坐标已经
     以旋转中心为原点
   - `metadata.json`：记录所有参数（角度方案、SOD/SDD/放大倍率、像素尺寸、
     mu、旋转中心等），以及一段可以直接抄的 ASTRA 导入代码
10. **样品评估**：对已加载的STL计算一组形态学参数（16个，按对"需要多少投影角度N"
    的预测重要性排序），1-7 默认勾选，8-16 默认不勾选，可以自己增减。点"计算并
    导出形态参数"后，连同当前的生成参数(SOD/放大倍率/像素尺寸/旋转中心等)一起
    写入输出目录下的 `shape_metrics.json`。
    - 1 Projection number N：直接读当前设的投影角度数，不是算出来的。
    - 2/4/6/7 L1/T5、Major dimension L1、Local thickness T5、L2/L1、L3/L2：
      L1/L2/L3 是 Krumbein/Sneed-Folk 意义下的三个互相垂直的最大尺度轴（最长轴、
      垂直于它的最长轴、再垂直于前两者的最长轴）；T5 是局部厚度分布的第5百分位
      （Hildebrand & Rüegsegger 1997 的最大内切球方法，体素化+距离变换实现，
      不是简单的"到最近表面距离"，有做"覆盖球"修正）。
    - 3 Equivalent diameter / Volume：D_eq=(6V/π)^(1/3)。
    - 8 Sphericity Ψ：Wadell(1932)公式, Ψ=π^(1/3)(6V)^(2/3)/A。
    - 9 SA/V：表面积/体积。
    - 10 Porosity：假设最大体积的壳是外壳，其余壳都是内部空腔，
      porosity=空腔体积/外壳体积（对多壳网格有效，单壳网格返回0）。
    - 11 Convexity/Solidity：V/凸包体积、凸包面积/实际面积。
    - 12 Euler characteristic：直接用 trimesh 的 `euler_number`。
    - 13 Surface roughness：**近似值** —— 原网格顶点相对Taubin平滑后网格的
      位移 Sa/Sq，不是真正的光学轮廓仪测量（任意实体没有一个"参考平面"）。
    - 14 Fractal dimension：体素化后做 box-counting，光滑物体在有限体素分辨率
      下算出来不会精确等于理论值(如实心球应趋于3)，这个参数本身在源表格里也
      标注"第一版不建议"，结果只适合同分辨率下样品间的相对比较。
    - 15 Tortuosity：**近似代理指标** —— 真正的多孔介质弯曲度需要一个流动通道，
      对任意实心样品没有标准定义；这里算的是"表面测地距离/直线距离"（两个
      L1端点之间沿网格表面走的最短路径长度，除以它们的直线距离），仅供参考。
    - 16 Principal-axis orientation：惯性主轴方向 + 相对XYZ全局轴的夹角。
    - 计算 T5/fractal dimension 需要先把STL体素化，面板里可以调"体素分辨率"
      （默认64，沿最长边的体素数，越大越准但越慢）。
11. **序列生成**：做"采样密度扫描"实验时，不用每次手动改N再点一次生成——填
    多段 `(起始N, 结束N, 步长)`（比如 100-1000 步长100，1000-3000 步长200），
    点"预览N列表"看合并去重后的完整N值列表，确认没问题再点"开始批量生成序列"。
    - 每个N单独生成到 `out_dir/N_00100/` 这样的子文件夹（5位数字补零），互不
      覆盖；其余参数（几何/采样方式/mu等）全部沿用当前设置，只有N变。
    - 后台线程跑，不卡界面；有总进度条（第几个N）和当前N内部进度条两层。
    - 勾选"跳过已生成过的N"（默认勾选）：某个N的子文件夹里已经有
      `projections.npy` 就直接跳过，方便序列跑到一半中断后接着跑，不用从头来。
    - 中途可以点"停止"，当前正在跑的N会跑完，后面还没开始的N不再跑。
    - 全部跑完（或被停止）后，在 `out_dir` 下生成一份 `sequence_summary.json`
      汇总表：每个N对应的状态（ok/skipped_existing/failed/cancelled）、子文件夹
      路径、耗时；单个N失败不会中断整个序列，错误详情记在对应条目里。

12. **批量实验(N搜索)**：这是核心功能——给一批不同的STL样品，每个样品自动
    跑"生成投影 -> ASTRA重建 -> 和ground truth算SSIM -> 根据SSIM调整N -> 重复"
    的闭环，直到SSIM落在目标值附近。不用手动一个个改N、跑重建、算SSIM。
    - **样品列表**：点"+ 添加STL文件..."多选，或"+ 添加文件夹内所有STL"整
      个文件夹一次性加进去；旋转中心对每个样品都自动用它自己的质心（不是
      "旋转中心"面板里手动填的那个值，因为不同样品几何中心不一样）。
    - **搜索参数**：目标SSIM、起始N、N上下限、SSIM容差、N收敛容差、单样品
      最大搜索次数——搜索策略是"倍增/减半找区间, 再二分收敛", 从起始N开始,
      SSIM不够就倍增N直到跨过目标, 再在跨过目标的区间里二分; 如果一直加到
      N上限还没跨过目标(或一直减到下限), 说明目标在当前其它参数下不可达,
      会如实返回"已尝试过的最接近目标的点", 不会假装收敛了。
    - **重建参数**：算法(`SIRT3D_CUDA`/`CGLS3D_CUDA`/`FDK_CUDA`) + 迭代次数
      (仅迭代算法用)、重建体素分辨率(每边体素数)、重建体积边界余量(相对样品
      半径的倍数，默认1.3，留一点空隙避免样品贴边被裁切)。
    - **"每个样品自动匹配像素尺寸"**（默认勾选）：复用"锥束几何"面板里那个
      自动适配FOV的算法，按每个样品自己的实际尺寸算像素尺寸，忽略手动填的
      像素尺寸值——不然不同大小的样品用同一个像素尺寸，小样品可能没填满探
      测器、大样品可能被裁切。
    - **"同时计算样品形态参数"**（默认勾选）：复用"样品评估"面板里当前勾选
      的那些参数（rank 1-16），用收敛后的N计算，一起存进结果里——这样每个
      样品的"形态复杂度"和"需要多少N才能达标"直接对应上，是这整套工具最初
      要验证的那个关系。
    - 后台线程跑，不卡界面；停止按钮是协作式的（当前样品/当前搜索点跑完才
      停，不会跑坏文件）。
    - **每个样品的输出**（存到 `out_dir/<样品名>/`）：
      - `projections.npy` / `astra_vectors.npy` / `metadata.json`：收敛N下
        最终那一组投影数据（跟"生成全部4π投影"输出格式完全一样，能直接导入
        别的ASTRA脚本）
      - `reconstruction.npy`：ASTRA重建出来的体素体积（float32, mu*长度量级）
      - `ground_truth.npy`：GPU光追做的二值ground truth占据网格（跟
        reconstruction.npy严格同一个网格，uint8）
      - `experiment_result.json`：收敛N、最终SSIM、是否达标(`target_reached`)、
        完整搜索历史(每次试的N和对应SSIM)、形态参数
    - **整体汇总**：`out_dir/batch_summary.json`，把所有样品的结果拼在一起，
      方便一次性看完这批实验（单个样品失败不影响其它样品，错误记在对应条目里）。

    **重要提醒**：目标SSIM能不能达到，不只取决于N——重建体素分辨率、迭代次数、
    探测器分辨率这些如果设太低，SSIM会早早封顶，加多少N都上不去（实测过一组
    64³体积+64x64探测器+SIRT 50次迭代的组合，N从200加到2000，SSIM只从0.48涨到
    0.51）。如果搜索总是卡在N上限或下限还是不达标，先把体素分辨率/迭代次数
    调高再试，别一直加N。

### 已有数据集手动导入 ASTRA（不用批量实验面板时）

用"生成全部4π投影"或"序列生成"跑出来的数据，手动导入 ASTRA 重建：

```python
import astra, numpy as np
vectors = np.load('astra_vectors.npy')
proj = np.load('projections.npy')       # (n_views, rows, cols)
rows, cols = proj.shape[1], proj.shape[2]
proj_geom = astra.create_proj_geom('cone_vec', rows, cols, vectors)
sino = np.transpose(proj, (1, 0, 2))     # astra 要的顺序是 (row, view, col)
proj_id = astra.data3d.create('-sino', proj_geom, sino)
```

或者更方便的：直接用下面的重建查看器打开这份数据，点几下就能重建+3D查看，
不用写代码。

## 重建查看器 (recon_viewer_gui.py)

独立程序，专门做"重建 + 3D查看 + 量化对比"，跟投影生成器的STL切片流程完全
解耦（不需要加载/切片STL）。界面：左侧是导入/重建/参考模型/显示设置，中间是
交互式3D等值面（拖拽旋转、滚轮缩放——复用投影生成器同一个
[mesh_viewer.py](mesh_viewer.py)组件），右侧是三张放大的正交切片（纵向排列，
比中间那个3D视图窄一点但每张图更大，方便看细节）。

这里的3D视图跟投影生成器里的STL预览用的是同一个组件，但显示模式不一样：
STL预览那边坐标轴/网格是固定的（因为绝对坐标对CT几何有意义），这边因为只
关心形状本身，把网格/刻度/数字全部去掉了，换成左下角一个跟着模型一起转的
小坐标轴指示器（红=X、绿=Y、蓝=Z，类似CAD软件常见的那种角标），界面更干净。

1. **导入重构后的三维模型 (.npy)**：直接打开一个体积数组文件（比如批量实验
   面板输出的 `reconstruction.npy`），跳过重建这一步，直接看。旁边有个"体素
   物理尺寸(mm/voxel)"输入框——原始的`.npy`文件本身不带物理尺寸信息，默认给
   1.0，如果你知道这份体积实际对应多大（比如是用体素分辨率96、体积半宽10mm
   重建出来的，那就是 2×10/96≈0.208），填对了3D视图里的尺寸才准；不填也不
   影响看形状，只是尺寸单位不对。
2. **导入投影/切片数据集进行重建**：选一个包含 `projections.npy` /
   `astra_vectors.npy` / `metadata.json` 的文件夹（"生成全部4π投影"/"序列
   生成"/"批量实验"的输出都符合这个格式），设好重建算法/迭代次数/体素分辨率/
   体积半宽，点"运行重建"，后台线程跑（不卡界面）。跑完左侧会显示**重建信息**：
   算法、迭代次数、体素分辨率、投影角度数、探测器分辨率、**重建耗时（秒）**、
   计算设备（GPU型号），方便不同参数配置之间量化对比。
3. **参考模型 (用于计算SSIM)**：浏览加载一个参考STL，跟当前重建结果算SSIM——
   如果是用"导入投影/切片数据集进行重建"这条路径重建的，且数据集的
   `metadata.json` 里记的原始STL文件还在，会**自动帮你加载**这个参考STL并
   算SSIM，不用手动选（跟批量实验面板里"自动加载参考STL"是同一个逻辑）；也
   可以手动换成别的STL对比。计算设备下拉框选GPU还是CPU（这一步需要GPU占据
   判定，用的是投影生成器同一套Warp光追）。SSIM结果旁边也带着计算耗时。
   - "导入重构后的三维模型 (.npy)"这条路径没有元数据，需要手动填"线性吸收
     系数 mu"（跟生成投影时用的mu一致才对得上）才能算SSIM；默认假定体积
     居中于原点、体素尺寸用"体素物理尺寸"那个输入框的值。
4. **等值面显示设置**：一个阈值滑块，实时用 `skimage.measure.marching_cubes`
   在当前阈值下重新提取等值面网格并显示——阈值越高，看到的等值面越"往内缩"
   （只有密度更高的区域才会被显示出来），这样能大致感觉出重建结果的密度分布，
   不是只有一个固定的外壳。默认阈值用Otsu方法自动选，不是简单的最小值-最大值
   取中点（原因见下面"已验证"一节）。
5. **导出当前等值面为 STL**：把当前阈值下提取出的网格存成STL，可以拿去别的
   CAD/网格软件里进一步检查。
6. 右侧的正交切片（X/Y/Z三个滑块，各自独立拖动）用来看等值面遮住的内部
   细节——等值面只显示"表面"，内部结构（比如是否有该有的孔洞、局部密度是否
   均匀）得靠切片才能看到。

## 已验证

用解析球体（半径 R=10mm）做了单元测试：过球心的射线路径长度应为 2R=20mm，
GPU 计算结果与解析值误差 <0.03mm（来自网格离散化本身，非算法误差），GPU/CPU
两种设备结果一致。GUI 端到端流程（加载模型 -> 预览 -> 批量生成 -> 落盘）已用
离屏模式跑通。

形态参数模块也用解析形状验证过：实心球（R=5mm）算出 sphericity≈0.9998、
SA/V≈0.6006（理论3/R=0.6）、solidity/convexity≈1.0、euler=2、L1≈L2≈L3≈10mm、
局部厚度T5≈10.2mm（符合"整个实心球都是一个最大内切球, 所以处处厚度=直径"的
理论预期）；长方体（10x8x6mm）算出 L1=14.142mm（=空间对角线）、solidity=1.0、
SA/V 精确匹配解析值；用两层同心球壳模拟含内部空腔的样品，porosity 算出0.216，
和解析值(4/3π3³)/(4/3π5³)=0.216 一致。

注：Local thickness 对尖锐直角边非常敏感——一个没有圆角的长方体，其5%分位
厚度会因为8个角/12条棱附近的"最大内切球"迅速缩小到体素尺度而显得很小，这是
Hildebrand-Rüegsegger算法本身的正确行为（棱角处确实局部很"薄"），不是bug；
真实CAD零件通常有圆角，不会这么极端。

重建+SSIM+批量实验这条链路验证过三层：
1. **GPU ground truth 正确性**：球体(R=5mm)在边长1.5R的立方体网格里占据比例
   算出0.1546，解析值(4/3πR³)/(1.5R×2)³=0.1551，几乎精确匹配；速度0.03秒
   (96³=884736个查询点)——同样的点集用trimesh的CPU版`mesh.contains()`跑了
   10分钟以上都没跑完，直接放弃换成GPU版本。
2. **SSIM计算本身**：自比较(gt vs gt)=1.0，vs随机噪声≈0.001，都符合预期，
   说明SSIM这一步没算错。
3. **真实端到端**：球体300视角+SIRT3D_CUDA 100次迭代，重建和ground truth的
   SSIM=0.796，是一个合理的中等重建质量数字；`n_search.py`的倍增+二分算法
   先用一条解析的饱和曲线（sigmoid型）单元测试过6种边界情况（正常收敛、从上
   方/下方逼近、已经在目标上、目标太高/太低不可达、协作式取消），全部通过；
   再接上真实的GPU生成+ASTRA重建+SSIM跑过一次真实搜索，发现在某组参数下
   SSIM在N=200~2000之间几乎不涨（0.48->0.51），算法正确识别并报告"目标在
   当前参数下不可达"，不是卡死或算错。
   批量实验面板本身也用2个样品(球体+长方体)、极小分辨率跑通过一次完整
   端到端（含形态参数联动），产物文件齐全。

"直接生成再重建"和"先导出数据集再加载重建"这两条路径验证过一致性：同一个
球体样品，两条路径算出的SSIM完全一样（0.16385020776...精确到小数点后16位），
确认加载已导出数据集时读取的旋转中心/mu/分辨率这些元数据没读错（这个验证
是在把"单次重建实验"面板拆到独立的重建查看器之前做的，逻辑本身没变，拆分
只是换了个UI外壳）。

重建查看器（[recon_viewer_gui.py](recon_viewer_gui.py)）本身也验证过：合成的
一个球形密度场，等值面提取正常出网格；用一份随机噪声"投影"数据跑ASTRA重建
不报错、shape对；用真实生成的数据集重建后，阈值滑块从中间调到80%位置，等值面
面片数从1040降到48（数值合理——阈值越高，满足条件的体素越少，等值面越小/越
碎）；导出STL、直接加载现成的 `.npy` 体积文件也都验证过。

上线后发现过一次真实bug并修复验证过：40³合成球体（值0/1）里塞一个孤立噪声
体素（值100），如果用"最小值-最大值取中点"选默认阈值会算出50.0——这个值比
球体本身的密度(1.0)高49倍，默认视图会完全看不到球体，只可能勉强扫到那个
孤立噪声点附近，等值面因此变成稀碎的小面片（这正是用户反馈"看起来像散落
碎片"那张截图的根因）。换成 Otsu 方法后算出默认阈值0.977（准确卡在背景0和
前景1之间，没被那个孤立噪声点带偏），等值面正确长出5296个面片的球体网格。
同时修了等值面坐标没有换算成物理mm尺寸的bug（之前用的是体素序号 0~n，现在
`voxel_pitch × 坐标 - 半宽` 换算并居中到原点，跟重建体积本身的坐标约定一致），
用同一个例子验证了顶点坐标范围精确落在预期的±10mm内（体素尺寸0.5mm x 40体素
/2=10mm）。

重建查看器的SSIM对比功能用真实数据跑通过：生成一个球体样品的数据集(150视角,
48x48探测器)，导入重建(体素分辨率64, SIRT 100次迭代)，重建耗时0.11秒；因为
`metadata.json`里记的STL文件还在，自动加载了参考STL并算出SSIM=0.616（对一个
中等配置的球体重建，这是个合理的数值）。另外故意用一组"没先调像素尺寸自适配
就改分辨率"的错误参数复现过反例——SSIM算出0.051（明显异常低），确认了这个
低分数是我测试脚本自己的参数设置错误（探测器分辨率改了但没重新自适配像素
尺寸，导致投影生成阶段样品实际被裁切了一部分），不是SSIM功能本身的bug；这也
印证了SSIM作为质量指标确实对几何设置错误很敏感，能真实反映出问题。

## 已知限制 / 后续可扩展

- 假设模型是单一均匀材料（mu 是一个标量），STL 本身不带材料信息。
- 非水密网格（non-watertight STL）会导致路径长度积分出错，目前只做提示，不
  自动修复；需要的话可以后续接 `trimesh.repair` 或 pymeshfix。
- 旋转中心目前只能用数值输入，暂不支持在 3D 预览里鼠标点选。
- 未加噪声模型（Poisson noise 等），当前输出是理想无噪声的线积分。
- 采样方案 / 重建算法都是可插拔设计（`geometry.SAMPLING_SCHEMES` 字典 /
  `reconstruction.ALGORITHMS` 字典），对比 SIRT/CGLS/FDK 对稀疏4π采样的鲁棒性,
  可以直接在这套代码上扩展。
- 目标SSIM能不能达到不只取决于N，重建体素分辨率/迭代次数/探测器分辨率设太低
  的话SSIM会早早封顶——批量实验面板里这几个都做成了可调参数，"N搜索卡在
  上下限还是不达标"时先调这些，不是N搜索算法的问题（已在上面"已验证"里用
  真实数据确认过这个现象）。
- **`reconstruction.reconstruct()` 默认给 SIRT/CGLS 加了非负约束**
  (ASTRA的`MinConstraint=0`选项, `non_negative=True`参数控制, 只对迭代算法
  生效, FDK不受影响)。这是用一个真实薄壁/尖角样品(四叶草, 厚4mm)测出来的：
  不加这个约束, 单靠堆分辨率(128³→256³体素)和调迭代次数, SIRT的SSIM一直卡在
  0.78~0.83涨不动(迭代次数还越多越差, 典型的SIRT半收敛/噪声放大); 光是加上
  这一个约束, 同样的分辨率下SSIM直接跳到0.90——衰减系数物理上本来就不该是
  负数, 不加约束的话SIRT/CGLS在尖锐边缘附近容易震荡出负值伪影, 直接加分。
  CGLS在这个样品上明显不稳定(迭代越多越差), 目前没找到让它变好用的办法,
  SIRT+非负约束是目前测出来最可靠的组合。
- SSIM是在"整颗体积"上算的全局指标，样品在体积网格里占的比例、mu的归一化
  假设(重建值直接除以mu再clip到0-1)都会影响它的绝对数值，不同样品之间的
  SSIM不一定能直接比较大小，同一个样品内部随N变化的相对趋势更可信。
- 形态参数里 tortuosity 用 networkx 在网格的顶点图上跑最短路径，顶点数很大
  （几万以上）时可能明显变慢；local thickness 的体素网格分辨率越高也越慢——
  面板里的"体素分辨率"和要不要勾选这两项，都可以按需要调整。
- surface roughness / fractal dimension / tortuosity 三个都是**代理指标**
  （没有对任意实体的标准定义），已经在README和结果的 `note` 字段里写清楚了
  各自的近似方式，不要直接当成物理光学轮廓仪/多孔介质弯曲度的测量值来用。
- 拆出重建查看器一开始是为了省掉Warp那~350MB体积，但后来加了SSIM对比功能
  又把Warp加回来了（GPU ground truth占据判定绕不开它），现在两个exe体积
  基本一样大，独立拆分带来的体积收益已经没有了——保留独立拆分主要是因为
  UI/工作流本身仍然解耦（重建查看器不用管STL切片/采样方案这些），不是为了
  省体积。
- 等值面阈值目前只有一个全局滑块，没有做多阈值叠加显示或颜色映射到密度值
  这类更高级的可视化。
- 重建查看器打开时默认阈值用 Otsu 方法自动找（不是简单取最小值-最大值的
  中点），能顶住"重建结果里有个别噪声/边缘伪影像素把最大值拉得很高"这种情况
  （见下面"已验证"里的具体数字）；但 Otsu 本身假设数据大致是"背景 + 前景"
  两个群体，如果样品本身是多材料/多密度层次，默认阈值可能不是你想看的那一层，
  拖动滑块自己找。
